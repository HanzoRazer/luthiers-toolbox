# Options

## 1. Restore the refined suite as a routed feature

Ruled out.

`useHeadstock` is `NOT_RECOVERED_GENERATION_UNKNOWN`. Workspace, Parametric, and Configurator call it. The recovered types do not match `useDxfImport` or `useExportDxf` (11 errors). A second route would also mount the DXF exporter, the cost endpoint, and the CAM overlay beside the designer the consolidation already kept. That is the duplication this order was asked not to revive.

## 2. Port one design capability into `HeadstockDesignerView.vue`

Supported, for one cluster.

The designer is the page at `/art-studio/headstock`. It already collects outline-shaped inputs and then asks the inlay API for a prompt. `buildHeadstockPath` is a pure function in the recovered source, and `ParametricCanvas.vue` draws it without `useHeadstock`. That is enough to specify a preview. It is not enough to restore the suite.

`ArtStudioHeadstock.vue` stays a comparison surface. Nothing in the two files is a shared geometry or session contract.

## 3. Retain the suite as research and archive

This remains the status of every capability except the one cluster named in [RECOMMENDATION.md](RECOMMENDATION.md). The archive hashes stay under the existing preservation test. This order does not edit those files.

Outcome 3 is the correct result for interactive inlay, import, variants, wood-grain panels, and every DXF or CAM path. It is not the correct result for the parametric outline, because that function is present and does not need the missing module.
